## 三、数据模型

### 3.1 维度表（复用 / 新建）

| 表 | 说明 | 处理 |
|---|---|---|
| `customers` | 客户主表（账号=客户），存最新一份 | 改造：主键改 account_id，补 comp_id/global_id/公司名/客户经理/主管/行业/合同字段 |
| `users` / `roles` / `permissions` | 账号与权限 | 保留 |
| `user_customer_binding` | 用户↔客户经理 绑定表 | **新建**：user_id ↔ manager_name（可绑多个），行级隔离据此过滤 |
| `knowledge_docs` / `rules` / `goal_configs` / `app_settings` | 配置类 | 保留 |

### 3.2 事实表（历史快照，主键 = stat_date + account_id）

| 表 | 来源 CSV | 核心字段 |
|---|---|---|
| `snap_store` | 商家运营明细 | 到期日期、提前续约状态、P4P层级、推广状态、P4P月消耗、P4P现金余额、商品数、实力优品、超级优品、星级、近30天曝光/点击/询盘、近90天信保挂账金额/订单数、近90天信保交易成功金额、风险健康分数、生命周期 |
| `snap_milestone` | 180天新商明细 | 当前服务天数、6 里程碑的「数值+达标状态+达标天数」、是否达5000、续签高风险 |
| `snap_ad` | P4P消耗明细 | P4P当月/季度/财年消耗、现金余额、预算、近7/30/60/90/365天消耗、活跃/休眠/流失标记、品牌/顶展/问鼎/回眸/明星展位营收、点爆、推广计划数、商品数/优爆品 |
| `snap_camp` | AW成交营明细 | 品数、优品数、市场热卖定招品、AI知识库文件数、结构化商详品数、近30/90天买驱GMV、近30/90天实收GMV、中供/OKKI/品广/效果广告营收 |

### 3.3 订单流水表（非快照，增量追加）

| 表 | 来源 CSV | 说明 |
|---|---|---|
| `awb_orders` | AWB购买明细 | 主键 item_num，签约金额/付款金额/付款状态/付款日期/产品分类/新续属性；**公司名回填**：account_id 关联 customers 取完整公司名 |

### 3.4 保留 / 改造的业务表

- `renewal_snapshots`：续约快照 → 改为从 `snap_store` 计算生成（自算天数分级 + 官方状态）
- `opportunities`：售卖机会 → 保留表结构，规则重写
- `awb_payments`：旧的 AWB 付款表 → 被 `awb_orders` 替代，废弃
- `store_stats_monthly` / `ad_stats` / `product_stats`：旧的月度聚合表 → 被 snap_* 系列替代，废弃
- `work_logs` / `manual_actuals`：过程记录 / 手动录入 → 保留

### 3.5 原始兜底

每个事实表保留 `raw JSON` 列，存完整原始行，用于：列名变动回溯、后续扩展字段、审计。

## 四、数据导入机制

1. **扫描目录**：`C:\Users\TFKJ\Desktop\渠道数据导入\`（默认，可改）
2. **频率**：每天一次（默认每天 09:00，可配置）
3. **编码**：自动识别 GBK / UTF-8，统一转 UTF-8 入库（AWB 表已发现乱码）
4. **公司名回填**：AWB / 成交营 的脱敏公司名（"四*****�"），用 account_id 从 customers（由 P4P / 商家运营明细提供完整名）回填
5. **列名模糊匹配**：阿里导出列名可能变，按关键词模糊匹配（"消耗"→p4p_monthly_cost 等）
6. **幂等去重**：按「文件名 + 行数 + 内容 hash」去重，同一天重复导入不产生重复行
7. **导入日志**：记录每次扫描的文件、行数、成功/失败、错误明细

## 五、数据清洗规则

| 情形 | 处理 |
|---|---|
| 空值 | → NULL |
| 数值 `-1`（里程碑"未开始考核"） | → 保留 -1，前端显示"进行中/未开始"，不参与达标率分母 |
| 脱敏 `*****` | 照存，公司名用回填值 |
| 金额（含逗号/单位） | 去逗号、去单位，统一存数值（元） |
| 日期 | 统一 YYYY-MM-DD |
| GBK 乱码 | 编码转换后重读；仍乱码的标记待人工 |

## 八、售卖机会规则草案（基于真实字段，待审）

| 规则 | 触发条件 | 机会类型 |
|---|---|---|
| R1 续约加购 | 提前续约状态 ∈ {3个月内, 3~6个月} 且 P4P现金余额 > 0 | 续约 + 广告加购 |
| R2 广告产品售卖 | 近30天 P4P 有消耗 且 品牌/顶展/问鼎营收 = 0 | 广告产品（品牌/顶展/问鼎） |
| R3 育商提升 | 是否金品 = Y 且 优爆品 < 20 | 运营育商 |
| R4 充值续费 | P4P 推广状态 = 现金欠费 | 充值续费 |
| R5 激活唤醒 | 有余额 7 日休眠 = 1 或 消耗显著下降 = 1 | 激活唤醒 |
| R6 金品未开通 | 是否购买金品未开通 = Y | 金品开通 |
